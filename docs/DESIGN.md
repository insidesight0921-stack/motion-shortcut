# DESIGN.md

> 이 문서는 이 프로젝트의 **단일 디자인 기준**입니다.
> UI 코드를 작성·수정하는 모든 에이전트는 화면을 만들기 전에 이 문서를 읽고,
> 여기 정의된 토큰과 규칙만 사용합니다. 임의의 색·간격·폰트 크기를 새로 만들지 않습니다.
> 규칙과 요청이 충돌하면 사용자 요청이 우선하되, 충돌 사실을 한 줄로 알립니다.

---

## 1. Visual Theme & Atmosphere

**한 문장:** 군더더기 없이 밝고 넓은 화면 위에, 지금 해야 할 단 하나의 행동만 또렷하게 보이는 인터페이스.

핵심 성격 5가지:

1. **여백이 주인공** — 요소를 채워 넣지 않는다. 밀도를 낮추고 그룹 간 간격으로 위계를 만든다.
2. **한 화면 한 메시지** — 한 화면에는 주요 행동(primary action) 하나. 나머지는 전부 보조 위계로 내린다.
3. **색이 아니라 위계로 말한다** — 정보 구분은 회색 3단계와 간격으로. 브랜드 색은 강조가 필요한 한 곳에만.
4. **정직한 물성** — 그림자는 실제로 떠 있는 것에만. 장식용 그라데이션·글로우·유리 효과 금지.
5. **움직임은 설명이다** — 애니메이션은 "무엇이 어디서 왔는지"를 알려줄 때만 쓴다. 즐거움을 위한 모션은 넣지 않는다.

이 문서가 만들려는 인상: *"공들여 만들었는데, 공들인 티가 안 난다."*

## 2. Color Palette & Roles

### 2.1 명명 규칙

`--{target}-{role}-{variant}` 형태로만 참조한다.

- **target**: `bg`(면) / `text`(글자) / `border`(선) / `icon`
- **role**: `default` / `subtle` / `muted` / `brand` / `success` / `warning` / `danger`
- **variant**: 없음(기본) / `weak`(연함) / `strong`(강함)

컴포넌트 코드에서 **원시 hex를 직접 쓰지 않는다.** 항상 아래 시맨틱 토큰을 거친다.

### 2.2 Light mode

| 토큰 | Hex | 역할 |
|---|---|---|
| `bg-default` | `#FFFFFF` | 기본 페이지·카드 배경 |
| `bg-subtle` | `#F9FAFB` | 페이지 배경(카드가 흰색일 때 뒤로 깔림) |
| `bg-muted` | `#F2F4F6` | 입력창, 비활성 면, 코드 블록 |
| `bg-brand` | `#1B64DA` | 주요 버튼 면 (흰 글자 대비 5.4:1 확보) |
| `brand-accent` | `#3182F6` | 아이콘·선택 테두리·그래프 등 **글자가 아닌** 브랜드 요소 |
| `bg-brand-weak` | `#EBF3FE` | 선택된 항목, 브랜드 배지 배경 |
| `text-default` | `#191F28` | 제목·본문 (순수 검정 금지) |
| `text-subtle` | `#4E5968` | 보조 설명, 라벨 |
| `text-muted` | `#6B7684` | 캡션, 타임스탬프, placeholder |
| `text-disabled` | `#B0B8C1` | 비활성 텍스트 (정보를 담지 않을 때만) |
| `text-on-brand` | `#FFFFFF` | 브랜드 면 위 글자 |
| `text-brand` | `#1B64DA` | 링크, 텍스트 버튼 |
| `border-default` | `#E5E8EB` | 카드·구분선 (장식용) |
| `border-strong` | `#8B95A1` | 테두리만으로 구분되는 컨트롤 (대비 3:1 필요) |
| `bg-success` `text-success` | `#15C47E` / `#08805A` | 완료·증가 |
| `bg-warning` `text-warning` | `#FF9500` / `#9A5A00` | 주의 |
| `bg-danger` `text-danger` | `#F04452` / `#D6303E` | 오류·삭제·감소 |

> `bg-*` 계열은 **면**에, `text-*` 계열은 **글자**에 쓴다. 예를 들어 성공 메시지의 글자는 `#15C47E`가 아니라 `#08805A`다. 밝은 상태색을 글자에 그대로 쓰면 대비가 무너진다.

### 2.3 Dark mode

다크 모드는 라이트 모드의 색을 반전시킨 것이 **아니다.** 별도 스케일을 쓴다.
원칙: ① 순수 검정 배경 금지(#000 위 흰 글자는 번져 보임) ② 면이 위로 올라갈수록 밝아진다(그림자 대신 밝기로 높이 표현) ③ 채도 높은 색은 한 단계 밝고 옅게.

| 토큰 | Hex | 역할 |
|---|---|---|
| `bg-default` | `#16181D` | 페이지 바닥 |
| `bg-subtle` | `#1C1F26` | 카드 |
| `bg-muted` | `#242830` | 입력창, 떠 있는 면 |
| `bg-brand` | `#2563EB` | 주요 버튼 면 (흰 글자 대비 5.2:1) |
| `brand-accent` | `#5A9CFF` | 아이콘·그래프 등 글자가 아닌 브랜드 요소 |
| `bg-brand-weak` | `#1B2A44` | 선택 상태 |
| `text-default` | `#EDEFF2` | 제목·본문 (순수 흰색 금지) |
| `text-subtle` | `#A8B0BA` | 보조 설명 |
| `text-muted` | `#868E99` | 캡션 |
| `text-disabled` | `#5A616B` | 비활성 (정보를 담지 않을 때만) |
| `text-brand` | `#7FB0FF` | 링크 |
| `border-default` | `#2B303A` | 구분선 (장식용) |
| `border-strong` | `#4A515C` | 테두리로 구분되는 컨트롤 |
| `text-success` | `#3DD69B` | 완료·증가 |
| `text-warning` | `#FFB340` | 주의 |
| `text-danger` | `#FF6B75` | 오류·감소 |

### 2.4 색 사용 규칙

- 한 화면에 브랜드 블루로 칠한 **면(fill)은 최대 1개.** 나머지 행동은 텍스트 버튼이나 회색 버튼으로.
- 회색 텍스트는 **3단계까지만**(`default`/`subtle`/`muted`). 네 번째 회색을 만들지 않는다.
- 상태색(success/warning/danger)은 **정보 전달용으로만.** 장식이나 브랜딩에 쓰지 않는다.
- 색만으로 의미를 구분하지 않는다. 항상 텍스트나 아이콘을 함께 둔다.
- **`text-muted`는 `bg-default`(흰 면) 위에서만** 쓴다. `bg-subtle`·`bg-muted` 같은 회색 면 위에서는 한 단계 진한 `text-subtle`을 쓴다. (회색 위 회색은 대비 4.5:1을 못 넘긴다)
- 모든 텍스트 조합은 WCAG AA(본문 4.5:1) 이상. 이 문서의 값은 검증을 마친 조합이므로, 새 색을 추가할 때도 같은 기준을 통과시킨다.
- 금액의 증감처럼 문화권 차이가 있는 색은 프로젝트 시작 시 한 번 정하고 문서에 못박는다. (기본: 상승=`danger` 계열이 아니라 `success` 계열, 하락=`danger`)

## 3. Typography Rules

### 3.1 폰트

```
font-family: Pretendard Variable, Pretendard, -apple-system, BlinkMacSystemFont,
             system-ui, "Apple SD Gothic Neo", "Segoe UI", Roboto, sans-serif;
```

- **한글과 영문을 한 폰트로 통일한다.** 한글용/영문용 폰트를 섞으면 baseline과 굵기가 어긋난다.
- 숫자가 변하는 자리(금액, 카운터, 타이머)는 `font-variant-numeric: tabular-nums`.
- 폰트는 2종 이상 쓰지 않는다. 코드 표기에만 등폭 폰트 1종 허용.

### 3.2 스케일

| 토큰 | size / line-height | weight | 용도 |
|---|---|---|---|
| `display` | 32 / 42 (1.31) | 700 | 랜딩 히어로, 온보딩 첫 문장 |
| `title-1` | 26 / 35 (1.35) | 700 | 페이지 제목 |
| `title-2` | 22 / 31 (1.41) | 600 | 섹션 제목 |
| `title-3` | 18 / 26 (1.44) | 600 | 카드 제목 |
| `body-1` | 17 / 26 (1.53) | 400 | 기본 본문 |
| `body-2` | 15 / 23 (1.53) | 400 | 보조 본문, 리스트 |
| `caption` | 13 / 20 (1.54) | 400 | 캡션, 라벨 |
| `micro` | 11 / 16 (1.45) | 500 | 배지, 태그 (남용 금지) |

근거: 큰 제목일수록 행간 비율을 줄이고(1.3대) 본문은 1.5대를 유지한다. 한글은 라틴 문자보다 글자 밀도가 높아 라틴 기준 행간(1.4)을 그대로 쓰면 답답해 보인다.

### 3.3 한글 조판 규칙 (필수)

- **줄바꿈**: 본문 컨테이너에 `word-break: keep-all;` + `overflow-wrap: anywhere;`
  → 한글이 어절 중간에서 끊기지 않는다. **이 한 줄이 한글 UI 완성도의 절반이다.**
- **자간**: 본문 `letter-spacing: 0`. `title-1` 이상은 `-0.02em`, `display`는 `-0.03em`.
  한글 본문에 음수 자간을 주면 가독성이 떨어진다. 큰 글자에만 적용한다.
- **굵기**: 강조는 600(semibold)까지. 700(bold)은 `title-1` 이상 큰 글자에만.
  한글은 작은 크기에서 700을 쓰면 획이 뭉친다.
- **한 줄 길이**: 한글 본문 한 줄은 **28~40자**(약 `max-width: 32em`). 그 이상 늘리지 않는다.
- **문장 부호**: 마침표 뒤 공백 1칸, 말줄임은 `…`(U+2026), 물결은 `~`가 아니라 `–`(범위) 사용.
- **대문자 변환 금지**: `text-transform: uppercase`는 한글에 무의미하고 영문 혼용 시 어색하다.
- 텍스트 안에서 줄을 강제로 끊어야 하면 `<br>` 대신 `<span>` 단위 wrapping이나 `text-wrap: balance`(제목)를 쓴다.

## 4. Component Stylings

공통: 모든 인터랙티브 요소는 4가지 상태(default / hover / active / disabled)와 `:focus-visible`을 반드시 정의한다.

### Button

| 종류 | 배경 | 글자 | 용도 |
|---|---|---|---|
| Primary | `bg-brand` | `text-on-brand` | 화면당 1개 |
| Secondary | `bg-muted` | `text-default` | 보조 행동 |
| Ghost | 투명 | `text-subtle` | 취소, 3순위 |
| Danger | `bg-danger` | `#FFFFFF` | 파괴적 행동 |

- 높이: `lg 52px` / `md 44px` / `sm 36px`. 모바일 주요 버튼은 `lg`.
- radius: `12px` (높이 36px 이하는 `8px`)
- padding: 좌우 `20px`(lg) / `16px`(md)
- hover: 배경 밝기 −4%, active: `transform: scale(0.98)`
- disabled: `bg-muted` + `text-disabled`, `cursor: not-allowed`, opacity로 흐리지 않는다
- 로딩 중에는 버튼 폭이 변하지 않도록 라벨 자리를 유지한 채 스피너로 교체

### Input

- 높이 `52px`, radius `12px`, 배경 `bg-muted`, 테두리 없음(기본)
- focus: 배경 `bg-default` + `border-strong` 1px + `box-shadow: 0 0 0 3px` 브랜드 8% 틴트
- 라벨은 입력창 **위에** 고정 배치. placeholder를 라벨 대신 쓰지 않는다.
- 오류: 테두리 `danger` + 아래에 `caption` 크기 오류 문구. 오류 문구 자리는 항상 비워둬서 레이아웃이 흔들리지 않게 한다.

### Card

- 배경 `bg-default`, 페이지 배경은 `bg-subtle`
- radius `16px`, padding `20~24px`
- 그림자 없음. 구분은 배경 대비로. 그림자가 필요하면 `elevation-1`만.
- 카드 안에 카드를 중첩하지 않는다.

### List row

- 최소 높이 `56px`, 좌우 padding `20px`
- 구분선은 좌우 padding을 유지한 inset 라인(`border-default`)
- 오른쪽 화살표(`>`)는 실제로 이동하는 행에만

### Modal / Bottom sheet

- 모바일은 바텀시트, 데스크톱은 중앙 모달
- radius: 바텀시트 상단만 `20px`
- 배경 dim `rgba(0,0,0,0.5)`, 다크 모드도 동일
- 진입 애니메이션은 §7 참조. 닫기 버튼은 항상 좌상단 또는 우상단 고정 위치

## 5. Layout Principles

- **간격 스케일(4px 배수)**: `2, 4, 8, 12, 16, 20, 24, 32, 40, 48, 64, 80, 120`
  이 목록에 없는 값(예: 15px, 30px)을 쓰지 않는다.
- **의미별 기본값**
  - 같은 그룹 안 요소 사이: `8`
  - 라벨과 값 사이: `4`
  - 카드 안 섹션 사이: `16~20`
  - 섹션과 섹션 사이: `40`(모바일) / `64`(데스크톱)
  - 페이지 좌우 여백: `20`(모바일) / `24`(태블릿) / 그 이상은 컨테이너 중앙 정렬
- **컨테이너 최대 폭**: 일반 `1120px`, 읽기 중심 페이지 `680px`
- **정렬**: 좌측 정렬 기본. 중앙 정렬은 빈 상태·성공 화면 등 텍스트 3줄 이하일 때만.
- **위계는 크기가 아니라 간격으로 만든다.** 제목을 키우기 전에 위아래 여백을 먼저 늘린다.
- 그리드는 12컬럼. 다만 컬럼에 억지로 맞추기보다 위 간격 스케일을 우선한다.

## 6. Depth & Elevation

그림자는 **네 단계까지만** 존재하고, 대부분의 화면은 `0`과 `1`만 쓴다.

| 레벨 | 값 (light) | 용도 |
|---|---|---|
| `0` | none | 카드, 기본 면 — **기본값** |
| `1` | `0 1px 3px rgba(0,0,0,.06), 0 1px 2px rgba(0,0,0,.04)` | 떠 있는 카드, 스티키 헤더 |
| `2` | `0 4px 12px rgba(0,0,0,.08)` | 드롭다운, 팝오버 |
| `3` | `0 12px 32px rgba(0,0,0,.12)` | 모달, 바텀시트 |

- **다크 모드에서는 그림자를 쓰지 않는다.** 대신 `bg-subtle → bg-muted`로 면을 밝혀 높이를 표현한다.
- 그림자에 색을 넣지 않는다(브랜드 컬러 글로우 금지).
- `backdrop-filter: blur()`는 상단 고정 바와 모달 dim에만. 카드에 쓰지 않는다.

## 7. Motion & Interaction

### 7.1 토큰

| 토큰 | 값 | 용도 |
|---|---|---|
| `duration-fast` | `150ms` | 색 변화, hover, 체크박스 |
| `duration-base` | `220ms` | 펼침/접힘, 탭 전환 |
| `duration-slow` | `320ms` | 모달·바텀시트 진입, 페이지 전환 |
| `ease-standard` | `cubic-bezier(0.4, 0, 0.2, 1)` | 대부분 |
| `ease-out` | `cubic-bezier(0.16, 1, 0.3, 1)` | 들어오는 요소 (감속이 길어 부드럽다) |
| `ease-in` | `cubic-bezier(0.4, 0, 1, 1)` | 사라지는 요소 |

### 7.2 규칙

- **320ms를 넘기지 않는다.** 넘으면 느리다고 느낀다.
- 들어오는 요소: `opacity 0→1` + `translateY 8px→0`. 이동 거리는 8px을 넘기지 않는다.
- 나가는 요소: 들어올 때보다 **빠르게**(`duration-fast`). 사라짐은 기다릴 이유가 없다.
- 누름 피드백: `scale(0.98)`, `duration-fast`. 모든 탭 가능한 면에 적용.
- 목록 항목을 순차 등장시키지 않는다(stagger 금지). 한 번에 나타난다.
- 무한 반복 애니메이션은 로딩 인디케이터에만.
- **`prefers-reduced-motion: reduce`를 반드시 처리한다.** 이동은 제거하고 `opacity` 전환만 남긴다. 이건 선택이 아니라 필수다.
- 레이아웃을 흔드는 속성(`width`, `height`, `top`)을 애니메이션하지 않는다. `transform`과 `opacity`만.

## 8. Do's and Don'ts

**Do**

- 화면을 만들기 전에 "이 화면에서 사용자가 할 단 하나의 행동"을 먼저 정한다.
- 빈 상태(empty), 로딩(skeleton), 오류 상태를 성공 상태와 같이 만든다.
- 로딩은 스피너보다 실제 레이아웃 모양의 스켈레톤을 우선한다.
- 숫자·금액은 천 단위 구분과 `tabular-nums`를 적용한다.
- 터치 타겟 최소 `44×44px`을 지킨다(시각적 크기가 작아도 히트 영역을 넓힌다).
- 키보드만으로 전체 흐름을 통과할 수 있게 하고 `:focus-visible` 링을 남긴다.

**Don't**

- ❌ 그라데이션 배경, 네온 글로우, 유리질(glassmorphism) 카드 — AI가 만든 티가 나는 1순위 요소
- ❌ 이모지를 아이콘 대신 사용
- ❌ 한 화면에 여러 개의 파란 버튼
- ❌ 아이콘과 텍스트가 같은 말을 반복 (🗑️ 삭제하기 → 텍스트 하나면 충분)
- ❌ 그림자 + 테두리 + 배경색을 한 요소에 동시 적용
- ❌ 정의된 스케일 밖의 값(회색 4번째 단계, 15px 간격, 새 radius)
- ❌ 중앙 정렬된 긴 문단
- ❌ 요소마다 다른 모서리 반경
- ❌ "성공적으로 처리되었습니다" 같은 시스템 말투 — 무엇이 어떻게 됐는지 구체적으로 쓴다
- ❌ 스크롤을 가로채는 커스텀 스크롤 애니메이션

## 9. Responsive Behavior

| 브레이크포인트 | 폭 | 기준 |
|---|---|---|
| `sm` | ~639px | 1컬럼, 좌우 여백 20px, 주요 버튼은 하단 고정 |
| `md` | 640~1023px | 2컬럼 허용, 좌우 여백 24px |
| `lg` | 1024~1279px | 사이드바 + 본문 |
| `xl` | 1280px~ | 컨테이너 1120px 중앙 정렬, 양옆은 여백으로 둔다 |

- 모바일에서 데스크톱 레이아웃을 축소하지 않는다. 요소를 **재배치**한다(테이블 → 카드 리스트).
- 모바일 주요 행동은 화면 하단 고정 영역에. 상단 우측 구석에 두지 않는다.
- 폰트 크기는 브레이크포인트마다 바꾸지 않는다. `display`와 `title-1`만 데스크톱에서 한 단계 키운다.
- 이미지는 종횡비를 고정해 레이아웃 이동(CLS)을 막는다.

## 10. Agent Prompt Guide

에이전트가 이 문서를 적용할 때의 체크리스트:

```
1. 이 화면의 주요 행동 1개는 무엇인가? → primary 버튼은 그것 하나뿐인가?
2. 쓴 색이 전부 §2 토큰에 있는가? hex를 직접 쓴 곳은 없는가?
3. 모든 간격이 4px 배수 스케일에 있는가?
4. 한글 본문 컨테이너에 word-break: keep-all이 들어갔는가?
5. 회색 텍스트가 3단계를 넘지 않는가?
6. 그림자를 elevation 0 또는 1로 끝낼 수 있는가?
7. 애니메이션이 320ms 이하이고 transform/opacity만 쓰는가?
8. prefers-reduced-motion 처리를 했는가?
9. 빈 상태·로딩·오류 화면을 만들었는가?
10. 다크 모드 토큰이 §2.3 값을 쓰고 있는가? (반전이 아니라 별도 스케일)
```

빠른 참조:

```
버튼면 #1B64DA / 브랜드악센트 #3182F6 / 본문 #191F28 / 보조 #4E5968 / 캡션 #6B7684 / 선 #E5E8EB / 배경 #F9FAFB
간격 4·8·12·16·20·24·32·40·48·64  |  radius 8·12·16·20  |  모션 150·220·320ms
```

---

### 부록: 값의 출처

- 회색 스케일(`#191F28`, `#4E5968`, `#6B7684`, `#8B95A1`, `#B0B8C1`, `#E5E8EB`, `#F2F4F6`, `#F9FAFB`)과 블루 `#3182F6`은 토스 공개 팔레트로 널리 인용되는 값입니다. **토스 공식 문서로 직접 확인한 값은 아닙니다. (미확인)**
- 버튼 면을 `#3182F6`이 아니라 `#1B64DA`로 정한 것은 의도적입니다. `#3182F6` 위의 흰 글자는 대비가 3.71:1로 WCAG AA(4.5:1)에 미달합니다. 토스 특유의 밝은 파랑은 `brand-accent`로 남겨 비텍스트 요소에 씁니다.
- 타이포 스케일의 크기·행간 비율은 토스 디자인 시스템(TDS) 공개 문서의 타이포그래피 토큰(30/40, 26/35, 22/31, 17/25.5, 13/19.5)을 참고해 웹 환경에 맞게 조정했습니다.
- 터치 타겟 44px, `prefers-reduced-motion` 대응은 Apple HIG / WCAG 기준입니다.
- 다크 모드 팔레트와 모션 토큰은 위 원칙에 맞춰 새로 설계한 값이며, 대비비는 WCAG AA 기준으로 검증했습니다.

## 적용 노트 (모션 단축키 프로젝트)

이 절은 원문 규칙을 이 프로젝트에 적용하며 둔 예외와 해석을 기록한다. 규칙 본문은 위와 같고, 충돌 시 이 절이 프로젝트 안에서 우선한다.

### 예외 1. 유지 진행 링 (HUD)

손바닥 0.5초·주먹 1.2초 유지 진행을 보여 주는 원형 링은 §7의 320ms 상한 **예외**다.
이유: 이 링은 "무엇이 어디서 왔는지"를 설명하는 애니메이션이 아니라 **지금 얼마나 유지했는지**를 나타내는 상태 표시다. 값은 인식 루프가 프레임마다 계산한 진행률이고, CSS는 `stroke-dashoffset`에 60ms 선형 전환만 걸어 프레임 사이를 보간한다. 진행률이 0.5초 또는 1.2초에 걸쳐 차오르는 것은 사용자의 행동 시간 그 자체이지 UI가 정한 지속 시간이 아니다. `prefers-reduced-motion`에서는 60ms 보간도 끈다(계단식 갱신).

### 예외 2. 개발 패널

우하단 "개발 패널"은 개발자 전용이라 §4 컴포넌트 규격(버튼 종류 1개 원칙 등)을 적용하지 않고 **토큰만** 지킨다. 기본은 접힘, Ghost 버튼으로 연다. 폭 420px, 로그 표 최대 높이 320px, 매핑 편집기 설정 칸 최소 폭 160px은 간격이 아니라 컨테이너 치수라 §5 간격 스케일 대상 밖으로 본다.

### 해석 1. 다크 모드의 면 역할

§2.3은 다크에서 `bg-default`가 페이지 바닥, `bg-subtle`이 카드라고 정한다(라이트와 반대). 컴포넌트가 테마마다 다른 토큰을 고르지 않도록 `--surface-page` / `--surface-card` / `--surface-raised` 별칭을 `tokens.css`에 두고 테마별 매핑만 바꾼다.

### 해석 2. 상태색 사용처

- 오류(카메라 실패)만 `text-danger`.
- 활성화 ON 표시(`text-success` + 점)와 타이머 완료 문구(`text-success`)는 §2.2 "완료·증가" 정보 전달로 허용.
- 실행 로그의 "실행"은 `text-default`, "변화 없음"은 `text-subtle`, "무시"는 `text-muted`. 상태색을 쓰지 않는다.
- 실행 예정(armed) 상태는 `text-warning`이 아니라 텍스트 "실행 예정"과 `brand-accent` 링으로만 표시.

### 해석 3. 주요 행동

이 화면의 primary는 "카메라 시작" 하나. 카메라가 켜지면 "카메라 중지"(Secondary)로 바뀌어 화면에 파란 면이 0개가 된다. 활성화 토글·효과음·개발 패널·영상 바꾸기·타이머 시작은 전부 Secondary 또는 Ghost.

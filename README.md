# Flickey

발표자의 자연스러운 몸짓과 명령 동작을 구분해, 슬라이드부터 커서·레이저·자료까지 제어하는 개인 맞춤형 모션 프레젠테이션 인터페이스. 팀 "곰팡이", 원티드 해커톤. 기획서는 [docs/PRODUCT.md](./docs/PRODUCT.md), 전환 기록은 [docs/DECISIONS.md](./docs/DECISIONS.md) D-017.

**현재 단계: 1차 — 발표 제어 기반.** 프로필, 슬라이드 명령(PowerPoint·Keynote·Google Slides 단축키), 로컬 에이전트 연결(+모의 에이전트), 모션 기본 OFF와 양손 X 켜기/끄기, 발표 대기 화면까지 있다. 커서·레이저 모드(2차), 자료 등록(3차), 리허설 보정(4차)은 아직 없다.

## 두 프로세스

| | 웹앱 (이 레포) | 로컬 에이전트 (팀원, 별도 코드) |
|---|---|---|
| 하는 일 | 카메라·손 인식·프로필·제스처 설정·발표 대기 화면·로그 | OS 키 입력, 시스템 커서, 레이저 오버레이 창, 자료 실행, 미니 패널 |
| 계약 | [docs/AGENT-PROTOCOL.md](./docs/AGENT-PROTOCOL.md) (`ws://127.0.0.1:41777`, JSON v1) | 같은 문서를 그대로 구현 |
| 없으면 | 페이지 안 폴백(합성 키 이벤트)으로 단독 데모. **발표 프로그램에는 닿지 않는다** | — |

개발 중에는 모의 에이전트를 띄워 메시지가 나가는지 확인할 수 있다.

```bash
pnpm mock-agent            # 41777 에서 대기, 받은 메시지를 콘솔에 출력
pnpm mock-agent -- --deny-accessibility   # 권한 없음 시뮬레이션
pnpm mock-agent -- --panic-after 5        # 5번째 메시지 뒤 긴급 정지
```

## 실행

```bash
pnpm install
pnpm dev
```

http://localhost:5173 을 열고 왼쪽 카드에서 "카메라 시작". 다른 프로젝트가 5173을 쓰면 `PORT=5174 pnpm dev`. Node 20.19 이상, pnpm 10 이상, Chrome 기준.

## 사용 흐름 (1차)

1. **홈**에서 발표 프로필을 만든다(이름, 프로그램). 이전 버전의 제스처 매핑이 있었다면 "기본 프로필"로 옮겨져 있다.
2. **프로필**에서 모션 켜기/끄기 제스처(기본: 양손 X 1초, 대안: 주먹 1.2초), 사용 손, 에이전트 포트를 정한다.
3. **제스처**에서 슬라이드 모드의 기능 ↔ 제스처를 확인·수정한다. 기본값은 아래 표.
4. **발표** 탭에서 카메라를 켜고 "발표 시작"을 누른다. 세션은 항상 `MOTION OFF`로 시작하고, 발표 시작이 슬라이드 모드로 켠다.
5. 발표 중에는 양손 X 1초, `Ctrl+Shift+0`, "발표 종료" 버튼으로 언제든 `MOTION OFF`.

| 제스처 | 슬라이드 모드 기본 명령 | 위험도 |
|---|---|---|
| 오른쪽으로 스와이프 | 다음 슬라이드 (→) | 낮음 |
| 왼쪽으로 스와이프 | 이전 슬라이드 (←) | 낮음 |
| 손바닥 펼치기 0.5초 | 화면 가리기 (B, 다시 하면 복귀) | 낮음 |
| 검지로 원 그리기 | 발표 화면 복귀 (Esc) | 높음 |
| 양손 X 1초 | MOTION OFF 켜기/끄기 | — |

프로그램별 단축키(발표 시작, 점프 등)는 `src/commands/programs.ts`에 있고 **실측 전 초기값**이다. 아래 실기 확인 항목 7에서 채운다.

## 안전 규칙

- 모션은 **기본 OFF**. `MOTION OFF`에서는 어떤 한 손 제스처도 실행되지 않고, 주먹으로도 켜지지 않는다. 켜는 경로는 양손 X, 화면, 키보드뿐.
- 모드 전환 직후 1.5초는 제스처를 받지 않는다.
- 에이전트 프로토콜에 삭제·이동·종료 메시지는 없다. 1차의 "높은 위험" 명령은 발표 화면 복귀(Esc) 하나이며 의도적인 제스처(원)에 배정돼 있다.
- 에이전트 쪽 긴급 정지(`panic`)를 받으면 즉시 `MOTION OFF`.
- 실행 로그에 실행 / 실행 실패 / 무시가 사유와 함께 남는다. 에이전트 응답 실패는 별도 줄로 "실행 실패 · 사유"가 뒤따른다.

## 개인정보 (기획서 §18)

- 영상은 이 기기 안에서만 처리되고 저장되거나 외부로 전송되지 않는다. 브라우저 밖으로 나가는 것은 로컬 에이전트로 보내는 명령 메시지뿐이다.
- 저장되는 것은 프로필(이름·프로그램·매핑·설정)뿐이며 `localStorage`(`motion-shortcut.profiles.v3`)에 있다. 리허설(4차)도 좌표 통계만 저장하고 원본 영상은 저장하지 않는다.
- 프로필을 지우면 그 안의 자료 슬롯·리허설 통계가 함께 지워진다.
- 카메라 상태는 왼쪽 카드와 홈에 항상 표시된다.

## 한계

- **페이지 안 폴백은 발표 프로그램을 제어하지 못한다.** 스크립트가 만든 키 이벤트는 `isTrusted=false`라 이 페이지 밖으로 나가지 않는다(D-015). 실제 제어에는 에이전트가 필요하다.
- 손 라벨(왼손/오른손)은 MediaPipe의 거울 가정 때문에 한 곳(`src/vision/handedness.ts`)에서 뒤집어 쓴다. 실기에서 반대로 나오면 상수 하나를 바꾼다.
- 카메라는 `localhost` 또는 HTTPS에서만 열린다. 배포 테스트는 Vercel 같은 HTTPS 호스팅이 필요하다.
- 음성 모드 전환은 실험 기능(프로필 설정 하단)이며 기본 꺼짐, 온라인에서만 동작한다.

## 1차 실기 확인 목록 (아직 확인되지 않은 것)

합성 좌표 유닛 테스트와 브라우저에서의 버튼·모의 에이전트 흐름만 확인했다. 카메라와 (가능하면) 실제 에이전트 앞에서:

1. **손 라벨**: 오른손만 들었을 때 오버레이에 `R`, HUD "감지된 손"에 오른손으로 나오는지. 반대면 `HANDEDNESS_FLIP`을 뒤집는다.
2. 두 손을 들었을 때 fps가 25 이상인지(한 손일 때와 비교).
3. 양손 X 1초 → `MOTION OFF` ↔ 켜기 토글, HUD 진행 링과 배지. 유지 중 한 손 제스처가 "양손 제스처 진행 중"으로 무시되는지. 5회 중 5회.
4. `pnpm mock-agent` 실행 후 발표 탭에 "에이전트 연결됨 · key/cursor/laser/open/panel"이 뜨고, 오른쪽 스와이프에 모의 에이전트 콘솔에 `{"type":"key","combo":"ArrowRight"}`가 찍히는지.
5. 모의 에이전트를 끄면 8초 안에 "에이전트 없음 · 페이지 안 폴백"으로 바뀌고 같은 제스처가 폴백 경로로 로그에 남는지, 다시 켜면 재연결되는지.
6. `--deny-accessibility`로 실행 시 로그에 "실행 실패 · 손쉬운 사용 권한 없음"이 뒤따르는지. `--panic-after 5`에서 6번째 메시지 뒤 `MOTION OFF`로 떨어지는지.
7. **프로그램별 단축키 실측표** (실제 에이전트 또는 수동 키 입력으로 확인해 `src/commands/programs.ts` 주석에 버전과 함께 기록):

| 명령 | PowerPoint (버전: ) | Keynote (버전: ) | Google Slides (브라우저: ) |
|---|---|---|---|
| next `→` | | | |
| prev `←` | | | |
| first `Home` | | | |
| goto `n`+Enter | | | |
| start | | | |
| blackout `B` | | | |
| return `Esc` | | | |

특히 `B`와 `n`+Enter 점프는 버전·브라우저에 따라 다를 수 있다.

8. 이전 버전 매핑이 있던 브라우저에서 첫 실행 시 홈에 옮김 안내가 뜨고 슬라이드 매핑에 이전 발표 매핑이 있는지.
9. 카메라를 켠 뒤 "발표 시작"이 primary(파란 면)로 바뀌고 카메라 시작 버튼은 Secondary가 되는지(한 시점에 파란 면 하나).

# 모션 단축키

웹캠으로 한 손 제스처를 인식해 요리 모드 화면(조리 영상, 조리 단계, 3분 타이머)을 손대지 않고 조작하는 웹앱. 팀 "곰팡이", 원티드 해커톤. **1차 초안** 상태다.

| 제스처 | 명령 |
|---|---|
| 손바닥 펼치기 (0.5초 유지) | 영상 재생/일시정지 |
| 오른쪽으로 스와이프 | 다음 조리 단계 |
| 왼쪽으로 스와이프 | 이전 조리 단계 |
| 검지로 원 그리기 | 3분 타이머 시작/정지 |
| 주먹 쥐기 (2초 유지) | 모션 단축키 활성화 on/off (꺼진 상태에서도 인식) |

방향은 **사용자 기준**이다. 미리보기가 거울 모드라 화면에서 보이는 방향과 같다. 활성화는 화면 우상단 버튼과 `Ctrl+Shift+M`(macOS도 Ctrl)으로도 켜고 끌 수 있다.

## 실행

```bash
pnpm install
pnpm dev
```

브라우저에서 http://localhost:5173 을 열고 "카메라 시작"을 누른다. 다른 프로젝트가 5173을 쓰고 있으면 `PORT=5174 pnpm dev`.

요구 사항: Node 20.19 이상(개발은 Node 26에서 함), pnpm 10 이상. Chrome 최신 버전에서 확인했다.

## 카메라 권한과 HTTPS

- 브라우저는 `localhost` 또는 HTTPS 페이지에서만 카메라를 열어 준다. `http://192.168.x.x:5173` 같은 LAN 주소로는 카메라가 열리지 않는다.
- 팀원과 배포 테스트를 하려면 Vercel, GitHub Pages 같은 HTTPS 호스팅이 필요하다. 정적 빌드(`pnpm build` → `dist/`)라 어디든 올릴 수 있다.
- 처음 접속 시 카메라 권한 팝업에서 "허용"을 눌러야 한다. 거부했다면 주소창 왼쪽 자물쇠 아이콘에서 다시 허용하고 새로고침한다.
- 손 인식 모델(WASM + `.task`)은 첫 실행 때 CDN에서 받는다(약 10MB). 오프라인 데모가 필요하면 `src/vision/assets.ts`의 안내대로 로컬 번들로 바꾼다.

## 알아 둘 제약

- **자동재생**: 제스처로 부르는 영상 재생은 브라우저 입장에서 사용자 입력이 아니다. "카메라 시작" 클릭이 먼저 있으므로 보통 재생되지만, 막히면 플레이어를 한 번 직접 클릭한다.
- **iframe 포커스**: YouTube 플레이어를 클릭한 직후에는 키보드 포커스가 iframe 안에 있어 `Ctrl+Shift+M`이 먹지 않는다. 제스처 명령이 실행되면 포커스를 돌려놓는다. 버튼이나 주먹 제스처는 항상 된다.
- **효과음**: 첫 클릭 이후에만 난다(브라우저 정책). 우상단 🔊 버튼으로 끌 수 있다.

## 개발

```bash
pnpm test        # 유닛 테스트 108개 (인식 로직·상태 머신·명령. 카메라 불필요)
pnpm build       # 타입 검사 + 프로덕션 빌드
pnpm typecheck
```

- 임계값은 전부 `src/gesture/config.ts`에 있고, 화면 우하단 **개발 패널**에서 실시간으로 바꿀 수 있다. 튜닝 절차는 [docs/GESTURES.md](./docs/GESTURES.md) "튜닝 방법".
- 실행 로그(하단)는 무시된 후보도 사유와 함께 남긴다. "복사" 버튼으로 텍스트를 가져와 이슈나 Claude Code에 붙여 넣는다. 브라우저 콘솔에도 `[motion]` 접두사로 같은 줄이 찍힌다.
- 구조와 규칙: [CLAUDE.md](./CLAUDE.md). 결정 기록: [docs/DECISIONS.md](./docs/DECISIONS.md). 개념 정리: [docs/LEARNING.md](./docs/LEARNING.md).

## 실기 확인 목록 (아직 확인되지 않은 것)

이 초안은 합성 좌표 유닛 테스트와 브라우저 렌더링만 확인했다. 실제 카메라 앞에서 아래를 확인해야 한다.

1. 카메라 시작 후 손을 들면 랜드마크가 **거울 미리보기 위의 손과 겹치는지** (어긋나면 오버레이 좌표 문제)
2. 오른손을 사용자 기준 오른쪽으로 옮길 때 HUD·로그에 `swipe_right`가 나오는지 (반대면 D-003 위반 — 임계값으로 고치지 말 것)
3. 손바닥 0.5초 → 재생/일시정지, 계속 들고 있어도 재실행되지 않는지
4. 주먹 2초 → 활성화 토글, 비활성 상태에서도 되는지, 계속 쥐고 있어도 다시 토글되지 않는지
5. 검지로 원 → 타이머 시작, 다시 원 → 정지. 원 그리는 도중 스와이프가 발동하지 않는지
6. 손바닥을 편 채 스와이프할 때 재생 토글이 먼저 발동하지 않는지 (`moving` 규칙)
7. 개발 패널의 손가락 비율이 펼친 손 1.2 안팎, 접은 손 0.8 안팎인지. 카메라를 비스듬히 볼 때는?
8. `Ctrl+Shift+M` 이 실제 키보드에서 동작하는지 (자동화 브라우저에서는 합성 키 입력이 전달되지 않아 확인 못 함)
9. 효과음이 첫 클릭 뒤에 나는지, 타이머 종료음이 울리는지
10. 30fps 근처가 나오는지(카메라 패널의 fps). 15 아래면 `delegate: 'CPU'`로 바꿔 비교

# 모션 단축키

웹캠으로 한 손 제스처 5개를 인식해, 사용자가 연결해 둔 명령을 브라우저 안에서 실행하는 개인용 모션 인터페이스. 팀 "곰팡이", 원티드 해커톤. 특정 상황에 묶이지 않는 **기본형**이며, 이 위에서 디벨롭 방향을 정한다.

| 제스처 | 기본 명령 |
|---|---|
| 손바닥 펼치기 (0.5초 유지) | 재생/일시정지 |
| 오른쪽으로 스와이프 | 앞으로 10초 |
| 왼쪽으로 스와이프 | 뒤로 10초 |
| 검지로 원 그리기 | 3분 타이머 시작/정지 |
| 주먹 쥐기 (1.2초 유지) | 모션 단축키 켜기/끄기 (고정, 꺼진 상태에서도 인식) |

방향은 **사용자 기준**이다. 미리보기가 거울 모드라 화면에서 보이는 방향과 같다. 활성화는 우상단 버튼과 `Ctrl+Shift+M`(macOS도 Ctrl)으로도 켜고 끌 수 있다.

## 실행

```bash
pnpm install
pnpm dev
```

브라우저에서 http://localhost:5173 을 열고 "카메라 시작"을 누른다. 다른 프로젝트가 5173을 쓰고 있으면 `PORT=5174 pnpm dev`.

요구 사항: Node 20.19 이상(개발은 Node 26에서 함), pnpm 10 이상. Chrome 최신 버전에서 확인했다.

## 사용법

### 모드

모드는 매핑과 데모 대상의 묶음이다. 미디어 · 읽기 · 발표 · 회의 4개와 대기 모드가 있고, 지금은 **미디어만 실제 대상이 있다**(나머지는 매핑만 있는 빈 프리셋). 전환 경로 세 가지는 항상 함께 동작한다.

| 경로 | 방법 |
|---|---|
| 화면 | 헤더의 모드 세그먼트 클릭, "대기" 버튼 |
| 키보드 | `Ctrl+Shift+1~4` (미디어·읽기·발표·회의), `Ctrl+Shift+0` (대기 진입/해제) |
| 음성 | "음성 켜기" 후 "발표 모드", "미디어 모드로 바꿔줘", "대기", "깨어나" 등 |

음성은 모드 전환과 대기 해제에만 쓴다. 명령 실행은 제스처가 한다. 전환 직후 1.5초는 제스처를 받지 않고, 안내음("발표 모드")이 한 번 나온다(끌 수 있음).

**대기 모드**에서는 모든 제스처가 무시되고 주먹으로도 풀리지 않는다. 카메라는 켜져 있지만 아무것도 실행하지 않는다는 약속이라, 해제는 음성("깨어나", "시작")·화면·키보드로만 한다. 우선순위는 대기 > 활성화 off > 활성화 on.

### 마이크 권한과 음성 인식의 제약

- 마이크는 "음성 켜기"를 눌렀을 때만 요청한다. 거부했다면 주소창 자물쇠 → 마이크 허용 후 새로고침한다.
- 인식은 브라우저가 아니라 Google 음성 서버에서 이뤄진다(Chrome). **오프라인에서는 동작하지 않는다.** Firefox는 미지원이고, 그 경우 "음성 미지원"으로 표시되며 화면·키보드 전환은 그대로 된다.
- 인식된 문장이 어떤 모드에도 맞지 않으면 로그에 "음성 | 무시 | 인식됨 · 의도 없음"으로 남는다. 자주 나오는 표현은 별칭에 추가하면 된다.

### 매핑 바꾸기

화면 오른쪽 위 "○○ 모드 매핑" 표에서 제스처마다 명령을 고른다. 모드마다 따로 저장되며, 바꾸면 바로 적용되고 이 브라우저의 `localStorage`(`motion-shortcut.mapping.v2`)에 남는다. 이전 버전(v1)에 저장해 둔 매핑은 처음 실행 때 미디어 모드로 옮겨진다. "기본값으로 되돌리기"는 현재 모드만 초기화한다.

| 명령 | 설정 | 동작 |
|---|---|---|
| 재생/일시정지 | — | 페이지의 YouTube 플레이어 토글 |
| 앞으로 이동 / 뒤로 이동 | 초 (1–600) | 재생 위치 이동 |
| 타이머 시작/정지 | 분 (1–180) | 카운트다운. 실행 중이면 정지 |
| 키 입력 | 키 조합 | 이 페이지에 키보드 이벤트 합성 (아래 한계 참고) |
| 없음 | — | 아무것도 하지 않음 |

각 행의 "테스트" 버튼은 제스처 없이 명령만 즉시 실행한다. 주먹은 활성화 on/off로 고정되어 바꿀 수 없다. 꺼진 상태에서 다시 켜는 유일한 제스처이기 때문이다.

### 키 캡처

"키 입력" 명령을 고르면 키 조합 칸이 나온다. 칸을 클릭한 뒤 원하는 키를 **실제로 누르면** `Shift+ArrowRight` 형태로 저장된다. Esc로 취소. 캡처 중에는 제스처 매핑 실행이 잠시 멈추고(로그에 "무시 · 키 캡처 중"), 스크립트가 만든 키 이벤트는 캡처되지 않는다.

### 데모 대상

오른쪽 아래에 명령이 실제로 동작하는지 볼 수 있는 대상 세 개가 있다. YouTube 플레이어(미디어 명령), 타이머, "마지막으로 받은 키"(키 입력 명령). YouTube 영상은 입력칸에 ID나 URL을 넣어 바꿀 수 있다.

## 한계

- **키 입력 명령은 이 페이지 안에서만 동작한다.** 스크립트가 만든 KeyboardEvent는 `isTrusted=false`라 브라우저 기본 동작(스크롤 등)과 YouTube 플레이어 같은 외부 콘텐츠에는 전달되지 않는다. "마지막으로 받은 키" 카드에 "합성 이벤트"로 표시되는 것이 그 증거다. 다른 웹앱을 제어하려면 SDK나 브라우저 확장 프로그램이 필요하며 이번 범위 밖이다([docs/DECISIONS.md](./docs/DECISIONS.md) D-015).
- **자동재생**: 제스처로 부르는 영상 재생은 브라우저 입장에서 사용자 입력이 아니다. "카메라 시작" 클릭이 먼저 있으므로 보통 재생되지만, 막히면 플레이어를 한 번 직접 클릭한다.
- **iframe 포커스**: YouTube 플레이어를 클릭한 직후에는 키보드 포커스가 iframe 안에 있어 `Ctrl+Shift+M`이 먹지 않는다. 명령이 실행되면 포커스를 돌려놓는다. 버튼이나 주먹 제스처는 항상 된다.
- **효과음**은 첫 클릭 이후에만 난다(브라우저 정책). 우상단 스피커 버튼으로 끌 수 있다.

## 카메라 권한과 HTTPS

- 브라우저는 `localhost` 또는 HTTPS 페이지에서만 카메라를 열어 준다. `http://192.168.x.x:5173` 같은 LAN 주소로는 카메라가 열리지 않는다.
- 팀원과 배포 테스트를 하려면 Vercel, GitHub Pages 같은 HTTPS 호스팅이 필요하다. 정적 빌드(`pnpm build` → `dist/`)라 어디든 올릴 수 있다.
- 처음 접속 시 카메라 권한 팝업에서 "허용"을 눌러야 한다. 거부했다면 주소창 왼쪽 자물쇠 아이콘에서 다시 허용하고 "다시 시도"를 누른다.
- 손 인식 모델(WASM + `.task`)은 첫 실행 때 CDN에서 받는다(약 10MB). 오프라인 데모가 필요하면 `src/vision/assets.ts`의 안내대로 로컬 번들로 바꾼다.

## 개발

```bash
pnpm test        # 유닛 테스트 159개 (인식 로직 102개 포함. 카메라 불필요)
pnpm build       # 타입 검사 + 프로덕션 빌드
pnpm typecheck
```

- 인식 임계값은 전부 `src/gesture/config.ts`에 있고, 화면 우하단 **개발 패널**에서 실시간으로 바꿀 수 있다. 튜닝 절차는 [docs/GESTURES.md](./docs/GESTURES.md) "튜닝 방법".
- 실행 로그(하단)는 실행 / 실행 실패 / 무시를 사유와 함께 남긴다. "복사" 버튼으로 텍스트를 가져와 이슈나 Claude Code에 붙여 넣는다. 브라우저 콘솔에도 `[motion]` 접두사로 같은 줄이 찍힌다.

## 실기 확인 목록 (아직 확인되지 않은 것)

모드·음성은 유닛 테스트와 브라우저에서의 화면·키보드 전환만 확인했다. 마이크와 카메라 앞에서 아래를 확인해야 한다.

**모드·음성**

1. "음성 켜기" → 마이크 권한 팝업 → "듣는 중"으로 바뀌는지. 거부하면 안내 문구가 나오는지
2. "발표 모드", "발표 모드로 바꿔줘", "미디어"라고 말했을 때 각각 전환되는지. 안 되면 로그의 "의도 없음" 문장을 복사해 둘 것
3. 안내음 "발표 모드"가 나온 뒤 같은 전환이 반복되지 않는지 (되먹임 방지). 스피커 볼륨을 높여서도 확인
4. "대기"라고 말하면 대기 모드, 그 상태에서 주먹을 쥐어도 아무 일이 없는지(로그 "무시 · 대기 모드"), "깨어나"로 해제되는지
5. 대기 중 "발표"(단독)는 무시되고 "발표 모드"는 전환되는지
6. 전환 직후 1.5초 동안 제스처가 "모드 전환 직후"로 무시되는지, 그 뒤 정상 실행되는지
7. 30초 이상 침묵 후에도 계속 "듣는 중"인지(자동 재시작). 와이파이를 끄면 오류 문구가 뜨는지
8. 이전 버전에서 저장한 매핑이 있었다면 첫 실행 때 미디어 모드에 그대로 있는지

**제스처·명령 (이전과 동일)**

1. 기본 매핑으로 손바닥 → 재생/일시정지, 오른쪽/왼쪽 스와이프 → ±10초, 원 → 3분 타이머가 실행되는지 (로그에 "실행")
2. 플레이어가 준비되기 전에 손바닥을 하면 로그에 "실행 실패 · 플레이어 준비 안 됨"이 남는지
3. 매핑을 바꾼 뒤(예: 손바닥 → 키 입력 `Space`) 제스처로 "마지막으로 받은 키"에 `Space · 합성 이벤트`가 뜨는지
4. 키 캡처 칸을 열어 둔 채 손바닥을 하면 로그에 "무시 · 키 캡처 중"이 남고 아무것도 실행되지 않는지
5. 새로고침 뒤에도 바꾼 매핑이 유지되는지, "기본값으로 되돌리기"가 동작하는지
6. 주먹 1.2초로 켜고 끄기가 여전히 되는지 (매핑 편집기에서 잠금 표시)
7. 매핑 편집기의 드롭다운에 포커스를 둔 채 키 입력 명령을 실행해도 드롭다운 값이 바뀌지 않는지 (합성 키가 body로 가는지)
